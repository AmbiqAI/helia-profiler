heliaPROFILER (`hpx`) builds firmware around a model, flashes it to an Ambiq
board, captures cycle counts and optionally power, and writes a result bundle
you can read, compare and script against. This section takes you from a
clean machine to that first bundle in six steps. Each step assumes the one
before it, so read them in order the first time.

## Purpose

By the end of this section you will have run one profile of a small
keyword-spotting model on an Apollo EVB, opened the summary it wrote, and
know which page to read next for the thing you want to measure. The pages provide commands, identify illustrative output, and explain
which checks need attached hardware.

## Prerequisites

A host running Linux, macOS or Windows, and an Ambiq Apollo EVB with its
on-board debug probe. Power capture needs a Joulescope
or an INA228 wired to the board; it is optional and comes later. The exact
versions are on [Hardware prerequisites](hardware-prerequisites/).

## What a run does

Every `hpx profile` invocation is the same sequence of blocks. The diagram
below is the shape to keep in mind while you read the rest of the section;
the [Concepts pages](../guide/concepts/) open each block up.

The same sequence as a list, for readers of the Markdown rendition:

- Configure: YAML and flags
- Analyse: model and memory
- Build: firmware
- Flash: J-Link
- Capture: PMU, power
- Report: result bundle

## Expected output

At the end of step 4 you have a `results/` directory holding
`result_manifest.json`, `summary.json`, `profile_results.csv`,
`run_metadata.json` and `nsx.lock`, and a per-layer table you can open in a spreadsheet.
Step 5 leaves you with an `hpx.yml` that reproduces that run from one
command.

## What next
