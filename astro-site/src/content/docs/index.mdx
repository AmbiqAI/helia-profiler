**heliaPROFILER (hpx)** shows ML and firmware engineers exactly how a model
performs on Ambiq silicon. One command builds firmware around the model,
flashes an Apollo EVB, captures per-layer cycles, hardware counters and
measured power, and writes a result bundle you can read, script, compare and
archive.

## How a run works

<BlockDiagram flow="row" density="compact" ariaLabel="The five stages of a run">
  <Block label="Resolve" sublabel="engine, board, counters" />
  <Block label="Build" sublabel="firmware around the model" />
  <Block label="Flash" sublabel="J-Link, then reset" />
  <Block label="Capture" sublabel="three windows" tone="muted" flow="column">
    <Block label="clean window" />
    <Block label="per-layer passes" />
    <Block label="power window" />
  </Block>
  <Block label="Report" sublabel="bundle and manifest" />
</BlockDiagram>

Resolve reads the engine, toolchain, board and counters from `hpx.yml` or
flags and refuses early with a hint. Build generates an NSX app around the
model with your memory placement and runtime overrides. Capture
runs a clean window for the cycle count, instrumented passes for the per-layer
rows, and a power window when a meter is attached. Report writes
`summary.json`, the per-layer CSV, run metadata, Model Explorer overlays and a
SHA-256 manifest. Already have two bundles? `hpx compare` runs on the host
with no hardware attached, and `hpx analyze model.tflite` inspects a model
before you build anything.

## Start measuring

<CardGrid columns={2}>
  <IconRow title="Per-layer cycles and PMU counters" icon="chart-simple" variant="outlined" href="/helia-profiler/guide/pmu-counters/">
    Every operator bracketed by hardware counter reads: cycles, instructions, stalls, cache and MVE events.
  </IconRow>
  <IconRow title="Measure power and energy per inference" icon="bolt" variant="outlined" href="/helia-profiler/guide/power/">
    Wire a Joulescope or INA228, gate the window on a GPIO, and read average power and energy with the window verified.
  </IconRow>
  <IconRow title="Compare engines and toolchains" icon="table-cells-large" variant="outlined" href="/helia-profiler/examples/engine-comparison/">
    Run the same model through heliaRT, heliaAOT, TFLM and ExecuTorch, or GCC against ATFE, on identical firmware.
  </IconRow>
  <IconRow title="Place memory and override the runtime" icon="memory" variant="outlined" href="/helia-profiler/guide/memory/">
    Put the arena, weights and code in TCM, SRAM, MRAM or PSRAM per run, and pass engine-specific settings through.
  </IconRow>
  <IconRow title="Compare two runs fairly" icon="scale-balanced" variant="outlined" href="/helia-profiler/guide/analysis-comparison/">
    hpx compare withholds a delta when the measurement conditions differ, so a number you quote is a real change.
  </IconRow>
  <IconRow title="See hot layers on the model graph" icon="diagram-project" variant="outlined" href="/helia-profiler/guide/model-explorer/">
    One Model Explorer overlay per counter, so a hot operator is a colour on the graph rather than a row in a CSV.
  </IconRow>
  <IconRow title="Read and reanalyse results" icon="file-lines" variant="outlined" href="/helia-profiler/guide/output/">
    Stable JSON and CSV schemas, issue codes for anything that degrades a run, and host-only reanalysis of any bundle.
  </IconRow>
  <IconRow title="Validate the bench" icon="circle-check" variant="outlined" href="/helia-profiler/getting-started/validate-your-setup/">
    hpx validate runs canonical models end to end across engines, toolchains and transports and proves the setup works.
  </IconRow>
</CardGrid>
