## Commands at a glance

| Command | Does |
|---|---|
| [`hpx profile`](cli/profile/) | build, flash, capture, report |
| [`hpx analyze`](cli/analyze/) | static model analysis on the host |
| [`hpx compare`](cli/compare/) | compare two result bundles, optionally against a regression profile |
| [`hpx validate`](cli/validate/) | the hardware-in-the-loop suite over the registered models |
| [`hpx doctor`](cli/doctor/) | check the toolchains and probes; `--bundle` writes a redacted support archive |
| [`hpx boards`](cli/boards/), [`hpx engines`](cli/engines/) | list the registered boards and engines |
| [`hpx probes`](cli/probes/), [`hpx ports`](cli/ports/) | list and match J-Link probes and host serial ports |
| [`hpx target`](cli/target/) | reset helpers for the attached board |
| [`hpx power-on`](cli/power-on/) | hold the instrument's passthrough power on |
| [`hpx cache`](cli/cache/) | inspect or purge the local build caches |

## Conventions

- `hpx profile model.tflite` is a shortcut for `model.path`; with a config
  file, omit the positional argument and pass `--config hpx.yml`.
- A flag on the command line overrides the same field in the config file;
  the resolved configuration is recorded in the run's `run_metadata.json`.
- `-v` adds `INFO` logs and `-vv` adds `DEBUG`; every subcommand accepts
  `--help`.
- Exit codes: 0 on success, non-zero on any `HpxError`, and 3 for an
  invalid run under `--fail-on-invalid`.
- Machine-readable copies of the generated surfaces sit beside each page
  (`cli.json`, `schema.json`, `issues.json`, the Markdown renditions and
  `llms.txt`), and every content page has a Markdown rendition at the same
  route with `index.md` appended.
