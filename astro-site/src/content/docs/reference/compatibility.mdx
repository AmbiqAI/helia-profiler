## Purpose

Answer "does this engine and toolchain run on this board" from records
rather than from memory. Every cell names one of four states and every
non-empty state points at its source.

## Prerequisites

None. To reproduce a hardware-validated cell you need the board named in
the row and the [Batch runs from YAML](../../examples/batch-runs/) recipe,
which is the nightly workflow.

## Status vocabulary

| Cell | Meaning | Source that can set it |
|---|---|---|
| hardware-validated | a case with this board, engine and toolchain passed in a recorded run of `.github/workflows/hardware-validation.yml` | the run's `validation_manifest.json` |
| compile-only | firmware for this combination built in CI without a board | no CI job builds firmware without hardware at the source tree this site was built from, so no cell carries it |
| experimental | the sources label the target best-effort and outside the compatibility guarantees | `guide/boards.mdx`, the board's config comments, `platform/board.py` (`is_fpga`) |
| unknown | no record either way | the absence of a source |

The board list is `hpx boards`, in registry order (`platform/registry.py`,
`list_boards()`); `channel` is the registry's `stable` or `preview` field.
The toolchains are the `Toolchain` enum in `vocab.py`: `arm-none-eabi-gcc`
and its alias `gcc` are one column, since both resolve to the GNU Arm
Embedded toolchain; `armclang` is Arm Compiler 6; `atfe` is the Arm
Toolchain for Embedded. The engines are the `EngineType` enum.

### 3. The record behind every hardware-validated cell

Nightly hardware validation [run 35078330526](https://github.com/AmbiqAI/helia-profiler/actions/runs/35078330526)
of 2026-09-16, suite `complete`, hpx 0.1.6 at source commit `0714893`,
over the MLPerf Tiny models `kws`, `vww`, `ic` and `ad`:

| Board | Cases | Passed | Engines run | Toolchains run |
|---|---|---|---|---|
| `apollo510_evb` | 32 | 32 | heliaRT, heliaAOT, TFLM, ExecuTorch | GNU Arm, ATfE |
| `apollo330mP_evb` | 32 | 32 | heliaRT, heliaAOT, TFLM, ExecuTorch | GNU Arm, ATfE |
| `apollo3p_evb` | 24 | 24 | heliaRT, heliaAOT, TFLM | GNU Arm, ATfE |
| `apollo4l_blue_evb` | 24 | 12 passed, 12 skipped | heliaRT, heliaAOT, TFLM | GNU Arm (ATfE skipped) |

Nine of the run's bundles ship under
[`examples/results/hardware-validation-2026-09-16/`](https://github.com/AmbiqAI/helia-profiler/tree/main/examples/results/hardware-validation-2026-09-16);
each `nsx.lock` records the module revisions the cell was validated with.
An `armclang` case does not exist in the nightly suite, so no cell in that
column is hardware-validated. ExecuTorch runs only in the Apollo5-family
cases of the suite; the Cortex-M4 rows are unknown for it, not unsupported.

## Expected output

A cell you can act on: hardware-validated means the recipe on
[Batch runs from YAML](../../examples/batch-runs/) reproduces it;
experimental means the wording on [Boards and targets](../../guide/boards/)
applies; unknown means nobody has recorded a result and a run of yours
would be the first.
