## Goal

Get one valid result bundle from a board and know what every line of the
terminal panel means. You will learn the shape of a run, the difference
between the two cycle totals it prints, and where the arena and binary
numbers come from.

## Hardware and wiring

An Apollo510 EVB connected to the host over its J-Link USB port. Nothing
else: the default transport is RTT over the debug connection, so no
serial cable and no power instrument. [Validate your setup](../../getting-started/validate-your-setup/)
confirms the probe sees the board.

## Software prerequisites

hpx (`pip install helia-profiler`), the GNU Arm toolchain, CMake and Ninja
on `PATH`, SEGGER J-Link software, and on Linux the udev rule
([Install](../../getting-started/install/)). `hpx doctor` must report the
toolchain and J-Link as found.

## Config file

[`examples/quickstart/hpx_rt.yml`](https://github.com/AmbiqAI/helia-profiler/blob/main/examples/quickstart/hpx_rt.yml):

```yaml
model:
  path: kws_model.tflite
  arena_size: 131072
engine:
  type: helia-rt
  config:
    variant: release-with-logs
target:
  board: apollo510_evb
  toolchain: arm-none-eabi-gcc
profiling:
  pmu_counters:
    cpu: default
    memory: default
  per_layer: true
  iterations: 3
  warmup: 1
power:
  enabled: false
output:
  format: csv
  dir: ./results/results_rt
```

The model path is relative to the config file, so run from
`examples/quickstart/` or pass the model on the command line. Every key is
on the generated [configuration reference](../../reference/configuration/).

## Run

```bash
cd examples/quickstart
hpx profile --config hpx_rt.yml
```

Or without a file, from anywhere:

```bash
hpx profile examples/quickstart/kws_model.tflite --board apollo510_evb --engine helia-rt
```

The first run resolves and builds the NSX dependency workspace, which
takes minutes; later runs reuse it.

## How to read it

- `Clean E2E cycles` is the inference cost: the firmware ran the model
  warm, back to back, with no per-layer instrumentation, and averaged 46
  inferences. `Total cycles` is the sum of the instrumented per-layer rows
  and is 0.4% higher because every operator was bracketed by a counter
  read. Publish the clean number ([Latency and per-layer](../../guide/latency/)).
- `Top Layers by Cycles` ranks the per-layer rows; `Cyc/MAC` divides by
  the operator's multiply-accumulates from the host-side model analysis.
  A depthwise convolution at 3.0 cycles per MAC next to a full convolution
  at 1.1 is the usual shape: depthwise has less arithmetic per byte moved.
- `Arena 29,780 / 32,768` is the interpreter's allocation against the
  configured `arena_size`; a run that reports the arena does not fit stops
  before flashing. The quickstart config asks for 131,072 bytes, which is
  what this model needs with headroom; the nightly case used 32,768.
- `Validity: VALID` and an empty issue list mean the run is a measurement.
  A `DEGRADED` or `INVALID` verdict lists codes to look up on the
  [issue codes](../../reference/issue-codes/) page.
- The five files are described on [Output files](../../guide/output/);
  `summary.json` has every number above in machine-readable form.

## Variations

- Other boards, same config with `--board`: the same nightly run profiled
  this model on `apollo330mP_evb` (2,056,992 clean cycles, Cortex-M55),
  `apollo3p_evb` (10,186,141, Cortex-M4, DWT cycle counter only) and
  `apollo4l_blue_evb` (8,683,558, Cortex-M4); those bundles ship beside
  the Apollo510 one. Cortex-M4 boards capture cycles only, not the PMU
  groups ([Boards and targets](../../guide/boards/)).
- More iterations: `--iterations 20 --warmup 5` tightens the per-layer
  median; the clean window is sized separately by `window_target_ms`.
- Another engine or toolchain: [Compare engines](../engine-comparison/),
  [Compare toolchains](../toolchain-comparison/).
- A JSON bundle: `--output-format json` writes `profile_results.json`
  instead of the CSV.
