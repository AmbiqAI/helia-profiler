## Goal

Measure what the engine choice costs and buys for one model, holding
board, toolchain, transport, counters and iterations fixed. You will learn
how to run the same recipe three times, how `hpx compare` reports the
result, and why it withholds per-layer deltas across engines.

## Hardware and wiring

An Apollo510 EVB on its USB J-Link port; no power instrument. The board,
its default RTT transport and the J-Link are described on
[Boards and targets](../../guide/boards/) and
[Capture transports](../../guide/transports/).

## Software prerequisites

hpx with the `aot` extra for heliaAOT (`pip install 'helia-profiler[aot]'`),
the GNU Arm toolchain, CMake and Ninja, SEGGER J-Link software
([Install](../../getting-started/install/)). `hpx doctor` must pass.

## Config file

Three checked-in configs share the model, board, toolchain and counter set
and differ only in the `engine` block and the output directory:

| Engine | Config |
|---|---|
| heliaRT | [`examples/quickstart/hpx_rt.yml`](https://github.com/AmbiqAI/helia-profiler/blob/main/examples/quickstart/hpx_rt.yml) |
| heliaAOT | [`examples/quickstart/hpx_aot.yml`](https://github.com/AmbiqAI/helia-profiler/blob/main/examples/quickstart/hpx_aot.yml) |
| TFLM | [`examples/quickstart/hpx_tflm_baseline.yml`](https://github.com/AmbiqAI/helia-profiler/blob/main/examples/quickstart/hpx_tflm_baseline.yml) |

The heliaRT and TFLM configs also ask for the `memory` counter group;
`hpx_aot.yml` asks for `cpu` only, so add `memory: default` to it before
comparing per-layer columns, or expect them to differ.

## Run

From the repository root (the model paths in the configs are relative):

```bash
hpx profile --config examples/quickstart/hpx_rt.yml
hpx profile --config examples/quickstart/hpx_aot.yml
hpx profile --config examples/quickstart/hpx_tflm_baseline.yml
hpx compare results/results_rt results/results_aot --output-dir results/rt-vs-aot
hpx compare results/results_rt results/results_tflm_baseline
```

## How to read it

- The cycles are close because all three engines run the same CMSIS-NN
  kernels for this model; the engine decides dispatch, not arithmetic.
  A model with operators heliaRT fuses or heliaAOT specialises will show a
  larger gap.
- `binary.text` is where the engines differ: heliaAOT links only the
  operators the model uses, so `.text` is 45.7% smaller than heliaRT and
  `.data` shrinks because the model is compiled rather than embedded as a
  flatbuffer; `.bss` grows because the compiled model's activation and
  constant areas are static allocations. TFLM's `.text` carries the full
  upstream interpreter.
- `hpx compare` omits per-layer deltas when the operation sequences differ
  (heliaAOT reports the model's original operator indices, the
  interpreters report the runtime's), and it lists `engine`,
  `engine_version` and `architecture_flags` as informative dimensions so
  the report says what changed rather than hiding it. The rules are on
  [Analysis and comparison](../../guide/analysis-comparison/).
- Quote `latency.device_clean_infer_avg_cycles` as the inference cost;
  `total_cycles` is the instrumented per-layer sum
  ([Latency and per-layer](../../guide/latency/)).

## Variations

- ExecuTorch: the same nightly run profiled the KWS model as a `.pte`
  through `nsx-executorch` (14 layers, clean window 2,148,976 cycles on
  the same board); the bundle
  `apollo510_evb-kws-executorch-ns-arm-none-eabi-gcc-rtt-auto` sits beside
  the others. The export path is on [Engines](../../guide/engines/).
- TFLM reference kernels: copy `hpx_tflm_baseline.yml` and set
  `engine.backend: reference` to measure the un-optimised interpreter.
- A different model: keep the three configs and change `model.path` and
  `model.arena_size` in each; `hpx analyze model.tflite --engine helia-aot --compare`
  shows operator coverage before you build.
- Placement: `model.arena_location` and `model.weights_location` change
  the numbers more than the engine does for memory-bound models; keep them
  identical across the three runs ([Memory placement](../../guide/memory/)).
